# Move Claude Code CLI users

If your developers use the Claude Code CLI, set it up separately from the desktop app. The desktop app takes its provider settings from its Claude Desktop on 3P configuration, **[not from `ANTHROPIC_BASE_URL` or `settings.json`](https://code.claude.com/docs/en/llm-gateway-connect)**, and **[passes them to the Code sessions it starts](https://claude.com/docs/third-party/claude-desktop/code)**. The CLI reads environment variables, settings files, and **[Claude Code managed settings](https://code.claude.com/docs/en/managed-settings)**, which use **[a separate policy key](https://code.claude.com/docs/en/admin-setup)**.

This guide is for admins of organizations on Claude Enterprise plans.

This article is part of **[Move from Claude Enterprise to Claude Desktop on a cloud provider](https://support.claude.com/en/articles/18426225)**, which defines the terms wave, overlap period, and cutoff date.

**[The CLI and everything that runs locally work on every provider](https://code.claude.com/docs/en/feature-availability)**. After the move, developers sign in differently, your policies reach their computers differently, and some features aren't available.

## Connect the CLI to your provider

Set the provider variables for **[Amazon Bedrock](https://code.claude.com/docs/en/amazon-bedrock)**, **[Google Cloud](https://code.claude.com/docs/en/google-vertex-ai)**, **[Microsoft Foundry](https://code.claude.com/docs/en/microsoft-foundry)**, or an **[LLM gateway](https://code.claude.com/docs/en/llm-gateway-connect)**. Developers **[don't need a claude.ai browser login](https://code.claude.com/docs/en/authentication)**. With a gateway, set both the base URL and a gateway credential. With only the base URL, **[a saved claude.ai login stays the active credential](https://code.claude.com/docs/en/llm-gateway)**, so its limits and billing still apply. Before a team rollout, **[pin your model versions](https://code.claude.com/docs/en/third-party-integrations)**.

## Deliver policy to each device

**[Server-managed settings don't apply](https://code.claude.com/docs/en/server-managed-settings)** when a third-party provider or a custom base URL is set. Move those policies to **[managed settings on the device](https://code.claude.com/docs/en/managed-settings)**. You can deliver them as a `managed-settings.json` file, the `com.anthropic.claudecode` macOS profile, or the `HKLM\SOFTWARE\Policies\ClaudeCode` registry key. They take priority over user and project settings, apart from a few security-sensitive keys where a stricter value from a lower level still counts.

- **Limit which providers a computer can use:** Set **[`allowedProviders`](https://code.claude.com/docs/en/third-party-integrations)** (Claude Code v2.1.285 or later). During the overlap period, **[a list such as `["anthropic", "bedrock"]`](https://code.claude.com/docs/en/authentication)** lets developers use either one. After the move, list only the new provider. Keep "anthropic" on computers where users stay signed in to claude.ai in Claude Desktop, because their Cowork sessions are refused without it. For a gateway reached through `ANTHROPIC_BASE_URL`, list `"customEndpoint"` and put the gateway URL in the `env` block of the same managed source.

- **Remove old login settings:** With gateway credentials, **[remove `forceLoginMethod` and `forceLoginOrgUUID`](https://code.claude.com/docs/en/llm-gateway-rollout)**, because either key blocks gateway credentials at startup. On a cloud provider, those keys **[block a session only while certain credentials are still on the computer](https://code.claude.com/docs/en/authentication)**: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, an `apiKeyHelper` credential, or an API key saved by an earlier Claude Console login.

Developers can run `/status` to see the active provider and where their settings come from. For telemetry, network hosts, and updates, see **[Data usage](https://code.claude.com/docs/en/data-usage)**, **[Enterprise network configuration](https://code.claude.com/docs/en/network-config)**, and **[Advanced setup](https://code.claude.com/docs/en/setup)**.

## Track cost and usage

On Bedrock, Google Cloud, and Foundry, usage is **[billed per token to your cloud account](https://code.claude.com/docs/en/costs)**, and cost controls are in your cloud billing console. Through a gateway, usage is **[billed per token to whoever owns the credential the gateway forwards](https://code.claude.com/docs/en/llm-gateway)**. The claude.ai analytics dashboards and the Claude Code Analytics API don't cover this usage. For reporting by user, use **[OpenTelemetry](https://code.claude.com/docs/en/monitoring-usage)** or an LLM gateway.

## What to watch for during the overlap period

- **Server-managed settings take priority in sessions that still authenticate with claude.ai.** By default, Claude Code **[uses them and skips the managed settings on the device](https://code.claude.com/docs/en/server-managed-settings)**, with a few exceptions such as the `env` block and `allowedProviders`. If some developers stay on claude.ai, **[use server-managed settings for them and a file or OS policy for everyone else](https://code.claude.com/docs/en/admin-setup)**.

- **A saved claude.ai login stays on the computer.** Cloud provider credentials **[take precedence](https://code.claude.com/docs/en/authentication)** over it, and `/logout` **[is unavailable](https://code.claude.com/docs/en/amazon-bedrock)** once a cloud provider is active. If you want the login removed, have developers log out before you deploy the provider settings. Logging out also **[removes saved MCP server logins and plugin secrets](https://code.claude.com/docs/en/troubleshoot-install)**, so they'll need to authorize those again. With a gateway credential, `/logout` stays available, and you can **[run it to clear the saved login](https://code.claude.com/docs/en/llm-gateway-connect)**.

- **CLI policy can override part of your desktop policy.** By default, if a computer has Claude Code managed settings, a desktop Code session **[ignores the managed policy values that the desktop app supplies](https://claude.com/docs/third-party/claude-desktop/code)**. To use both, see `parentSettingsBehavior` in **[Deploy managed settings](https://code.claude.com/docs/en/managed-settings)**.

## Checklist for developers

**Before the move**

- Update Claude Code to the version your admins specify.

- Pull any cloud sessions you need into the terminal with `claude --teleport`. First make sure the session's branch is pushed to the remote, and clean your working tree.

- List the claude.ai connectors you use, so they can be added as MCP servers.

- Copy any skill you rely on out of `~/.claude/skills/synced/`, and list the synced plugins you'll need to reinstall.

**On the day you move**

1. Sign in to your cloud provider the way your admins describe, for example with `aws sso login`, `gcloud auth application-default login`, or `az login`.

2. Start `claude` and run `/status`. Check the provider, the model, and the settings source.

3. Reopen a recent session with `claude --resume` and confirm that it responds.

4. Tell your admins about any tool or connector that's missing.
